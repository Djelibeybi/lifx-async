## Judged dispositions for ROADMAP criterion 2 (recorded, not actioned)

ROADMAP success criterion 2 reads *"no repository **or published guidance** lists it among the
state-backed cached properties"*, which is broader than the SPEC's scoping of requirement 2 to
`advanced-usage.md` plus `AGENTS.md`. The cross-AI plan review flagged the gap so a verify pass
does not discover it as an apparent hole. Two surfaces were examined and both judged **not** a
state-backed-caching listing. Each disposition is recorded here and gated below, so the
judgement is checked rather than merely asserted.

**1. `docs/api/devices.md:343-364`, the `### Connectivity` section under `## Device
Properties`.** Judged NOT a listing. Verified: the file contains zero case-insensitive
occurrences of `cache`, `cached` or `caching` anywhere, so there is no caching list in it for
`connectivity` to be listed among. `## Device Properties` there is an API-reference container
heading for per-property prose, not a state-backed property list; the sibling section under it
is `### MAC Address`. The section's own text already describes the value as derived, saying the
device's frame-address report is authoritative once it has answered any request and that the
value comes from the mDNS TXT record until then. Correcting a heading name in the API reference
would be a cosmetic edit to a file SPEC places out of scope, and would collide with Phase 20's
`docs/` pass. **Disposition: no change. Gated by the `API-REFERENCE-MAKES-NO-CACHING-CLAIM`
check in Task 1's verify block, which fails if a caching claim is ever introduced into that
section.**

**2. `AGENTS.md:343`, the `**State Caching**: Device properties cache values to reduce network
requests` bullet under `### Key Design Patterns`.** Judged NOT a listing. It is a one-line
index entry pointing at the `### State Caching` section, names no individual property, and
therefore cannot list `connectivity` among anything. Rewriting it would restate the three-way
model in two places and invite exactly the drift `tests/test_repository_guidance.py` exists to
prevent. **Disposition: no change.** The `### State Caching` section it points at is where the
third category lands, so a reader following the pointer reaches the corrected model.

Record both dispositions in `16-03-SUMMARY.md` so verify-phase inherits the judgement rather
than rediscovering the question.
