## Corrected verification attribution (D-14, factual correction)

D-14's recorded next-action clause reads: *"confirm with a request, or with `discover()`, whose
UDP leg is unicast-verified."* The second half of that clause is **false against the
implementation**, verified during the cross-AI plan review and re-verified here:

- `discover()`'s UDP leg consumes `discover_devices_shared()` directly (`src/lifx/api.py:1112`)
  and performs no verification. A UDP broadcast reply is yielded as found.
- `discover()`'s **mDNS** leg calls `_discover_verified_devices_mdns()` (`src/lifx/api.py:1125`),
  whose candidate path opens a `DeviceConnection` and sends a correlated `Light.GetColor` or
  `Device.EchoRequest` and requires an answer before the device is yielded
  (`src/lifx/network/discovery/mdns/discovery.py:1361`).

So verification exists, and it is on the leg D-14 named as the unverified one. Publishing D-14's
clause verbatim would ship a false statement about a reachability mechanism to callers, on the
exact surface SPEC prohibition P4 governs.

**Resolution.** D-14's intent is honoured in full: the proxy paragraph still states that an mDNS
result proves an advertisement exists rather than reachability, and still names the next action.
Only the mechanism attribution is corrected, to say that `discover()`'s mDNS candidates must
answer a correlated device request before they are yielded. This is a factual correction to a
decision's supporting clause, not a reopening of the decision. The fifth approved-phrase fragment
locks the corrected mechanism, because the original four lock the proxy topic without locking
which leg verifies, so the contract would have stayed green while the wrong claim shipped. Task 2
adds the matching repository-wide negative so a future edit cannot reintroduce it.

Bounded discovery is already locked by the existing entries retained unchanged
(`ephemeral source port`, `legacy-unicast replies`, `does not join the multicast group`,
`does not receive unsolicited announcements`, `does not authenticate or correlate responders`,
`schedules re-broadcasts 0.6, 1.8, 3.6, 5.6 and 7.6 seconds later`,
`they are not scaled to the requested discovery timeout`,
`a due re-broadcast is sent only while discovery remains active`,
`does not extend the overall timeout`).
