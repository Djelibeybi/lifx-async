<objective>
Make the effects Conductor drop Thread participants from frame effects before it captures their
state, with the same `enable_thread` opt-in the factories have.

Purpose: ANIM-05 R3 and the Conductor half of R8. The Conductor is the library's own multi-device
consumer: today it captures, powers on, animates and restores a Thread participant exactly as a
WiFi one. "Dropped means dropped": an excluded participant gets nothing from the Conductor.

Output: the exclusion step in `start()` and `add_lights()`, the opt-in on `__init__`, the flag
passed to every factory, docstrings, MagicMock tests (D-08) and one emulator-backed test module.

**Ordering the plan relies on (D-04).** Exclusion is a separate step after
`_filter_compatible_lights()` and its existing capability-empty early return, so the Conductor
knows exactly when Thread exclusion alone emptied the list, which is the only raise condition.

**Ordering settled by the maintainer's adjudication (L512@92a657d); do not redesign it.**
`_filter_compatible_lights()` runs first by D-04, and most built-in frame effects'
`is_light_compatible()` loads capabilities when they are unknown, so a Thread participant whose
capabilities were never loaded receives that capability probe before it is excluded. That is
accepted by design as threat T-18-17: the SPEC's MUST NOT (`18-SPEC.md` Acceptance Criteria)
forbids only capture, power-on, frame and restore packets to an excluded participant, and the probe
is none of those. A participant with unknown connectivity reaching capture is not a real path:
Thread devices do not answer broadcasts, and every construction path records connectivity before
the Conductor sees the device (discovery metadata, `connect()`, `from_ip()`, or the Thread bit on
the first correlated reply, which is the capability query itself), as R1's Target already states.
A directly constructed object that has never exchanged a packet is out of scope; if one did reach
`_create_animators()`, the factory's own guard still refuses it. The emulator test opens both
devices first because that records the Thread bit exactly as the real path does; it hides nothing.
There is no second, pre-compatibility exclusion pass.
</objective>
