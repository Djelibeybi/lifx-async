<objective>
Require and lock the emulator release that carries the per-device Thread reply flag, adapt the
existing emulator fixtures to that release's API, and add one shared session fixture hosting
Thread and WiFi devices on a single `::1` endpoint with a per-serial packet recorder.

Purpose: D-07 makes the emulator change a blocking prerequisite recorded as this phase's first
wave, and D-06 makes the emulator, not patching, the only source of a Thread test device. Every
ANIM-05 acceptance test in plans 02 and 05 and the raw-path packet-log tests in plan 06 consume
the fixture built here.

**The required version.** lifx-emulator-core 3.9.0 (2026-09-09) added Thread device identity:
a device built with `connectivity="thread"` sets the frame-address `thread_connection` bit in
every reply header. 3.10.0 (2026-09-10) added IPv6 transport and Thread isolation: a Thread
device answers only untagged unicast received over IPv6, exactly as real Thread hardware does.
The dev-dependency constraint moves from `>=3.1.0` to `>=3.10.0`, the latest release and the
first one whose Thread device can be reached the way the library reaches real Thread hardware.
That constraint is a minimum, not a pin: `uv.lock` is what fixes the exact version, 3.10.0, that
every `uv run --frozen` uses, and a later targeted lock refresh may resolve a newer compatible
release (review L44@92a657d). Both releases are on PyPI and tagged `core-v3.9.0` /
`core-v3.10.0` in the operator's own `Djelibeybi/lifx-emulator` repository. No edit to that
repository is planned here.

**Version-coupled test seam.** lifx-emulator-core 3.10.0 exposes no public accessor for its
committed IPv6 socket, so the `::1` fixture's `IPV6_V6ONLY` read-back reaches the private
`EmulatedLifxServer._ipv6_transport` attribute (review L45@92a657d). That is acceptable against the
locked version, and it is recorded twice so a future emulator upgrade knows what to replace: in a
fixture comment and under a "Version-coupled test seams" heading in this plan's summary.

**What the bump breaks, measured by the planner in a scratch copy of this tree.** The default
suite still passes on 3.10.0 (4459 passed, 700 deselected), but it emits three un-awaited
coroutine warnings and one destroyed pending task, because 3.10.0 changed the emulator API in
three ways the fixtures depend on:

1. `EmulatedLifxServer.remove_device()` is now a coroutine. The three synchronous teardown
   calls (`tests/conftest.py:859`, `tests/conftest.py:896`,
   `tests/test_animation/conftest.py:336`) therefore never remove their device.
2. `EmulatedLifxServer.start()` now binds an IPv4 and IPv6 endpoint pair itself, setting
   `IPV6_V6ONLY` before the IPv6 bind. The repository's `::1` server subclass
   (`tests/conftest.py:302-336`) overrides `start()`, builds its protocol with the default
   `AF_INET` family and never registers it, so a Thread device on it would be filtered as
   "received over IPv4", and its unregistered protocol schedules an endpoint-loss task that is
   still pending at shutdown.
3. Every server now binds `::1` on the same port as its IPv4 endpoint. A port pre-probed free on
   `127.0.0.1` only (`get_free_port()`) can collide on `::1`, and the pair bind retries only
   when the requested port is 0.

**A Thread-capable matrix product is required.** The emulator refuses to build product 55 (the
original Tile, `create_tile_device()`'s default) as a Thread device: "Firmware (4, 200) exceeds
product 55's maximum (3, 50)". Product 173 (LIFX Path, a 3x2 matrix) builds, answers
`get_device_chain()` over `::1`, reports `Connectivity.THREAD`, and applies Animator Set64 frames,
all verified by the planner in the scratch copy.

Output: the raised minimum and its lock, the adapted fixtures, the `thread_emulator` fixture, and
`tests/test_thread_emulator.py` proving the fixture end to end.
</objective>
