## Cross-AI review revisions, round 2

Round 2 confirmed the approval gate, the comment-identifier read-back and the locked-spec blob
hash all reproduce, and found one way the plan could publish twice, plus three gates that could
report the wrong thing.

**HIGH, fixed: publication was not idempotent.** If execution stopped after `gh issue comment` and
before the URL was captured, the read-back run and the summary written, re-running Task 5 would
post a second permanent public comment on the same issue. The baseline was described only as
working notes, and no resume rule looked for a body that had already been posted. A duplicate
public comment cannot be unpublished, so this is the one irreversible failure in the phase.

Task 5 now resolves each comment before posting rather than posting and hoping. It lists the
issue's existing comments, retrieves each body and compares it byte for byte against the approved
draft, and branches on the count of exact matches: none means post, exactly one means recover that
comment's identifier and continue without posting, more than one means stop and report. The resume
rule is therefore derived from GitHub's own state rather than from a local file, which matters
because a local state file written after the post can be lost by the same interruption that makes
the resume necessary. A local transaction record is still written immediately after each post,
carrying the issue number, the draft's `git hash-object` blob id, the returned URL and the post
state, but it is corroboration rather than the mechanism.

The postconditions change with it. "The comment count is exactly one greater than the baseline"
holds only when this run posted; when it recovered an existing comment the count is unchanged.
Both branches are now named, so neither reads as a failure.

**MEDIUM, fixed: the anchored sweep missed two of the three stale shapes.** `(^|[^/])scripts/...`
matches the bare form but not `./scripts/foo.py` or `/repo/scripts/foo.py`, because `scripts`
follows a slash in both. Reproduced against a four-line fixture, where only the bare form matched.
The sweep therefore no longer proved the "no old path" claim its acceptance criterion makes. The
pattern is replaced by one that normalises `.planning/scripts/` to a token holding no `scripts/`
and then re-matches, which catches all three stale shapes, skips the relocated form, and still
reports a line carrying both a corrected and a stale reference. It is plain POSIX ERE, so it needs
no PCRE build, and it is character for character the pattern plan 15-02 task 4 uses, name lists and
order included. A fixture covering the bare, `./`-prefixed, repository-prefixed, relocated-only and
mixed shapes runs in this task's verify and asserts a match count of exactly 4, so the acceptance
boundary is executable rather than asserted.

**MEDIUM, fixed: three expected-zero gates exited non-zero exactly when they passed.** `grep -c`
prints `0` and exits `1` when it matches nothing, so a gate whose success condition is a zero count
fails by exit status on success. Confirmed locally. The affected commands were the requirement 2
exclusion check in Task 3 and the `pyproject.toml` coverage-exemption check in Task 2, and the
sweep of all five plans found no others of this shape. Both are rewritten to capture the count in a
substring and compare it with `test`, so a pass exits 0 and each gate's stated failing direction
matches the command's real exit semantics.

**LOW, fixed: the ROADMAP diff-count verify was soft.** It failed only when a line count "exceeds
the number of lines the action names as editable", a number the verify never stated, leaving the
executor to adjudicate it live, and its second clause about hunks reaching another phase entry was
unevaluable from a bare integer. It is replaced by a block comparison: the Phase 16, 18, 19 and 20
entries are extracted from the merge base with `main` and from the working tree and hashed with
`git hash-object`, and each pair must be identical. Phase 17 is compared the same way with its
`**Depends on**` line removed from both sides, which is exactly the one clause this task is
licensed to change. Verified against the current tree: all five blocks hash identically today, so
the gate starts from a known-good state.

**LOW, fixed.** The issue read-back now uses `diff --strip-trailing-cr`, so a GitHub API response
that normalises line endings to `\r\n` cannot fail a byte-for-byte comparison spuriously while the
text is in fact identical.

**LOW, fixed.** The `/tmp/comment-url-*.txt` files assumed a POSIX `/tmp`, and the verifies
depended on them surviving until the verify ran. They move to `${TMPDIR:-/tmp}`, and they are no
longer load-bearing: the comment identifier is resolved from GitHub by exact body match, so a lost
URL file degrades to a slower lookup rather than an unverifiable publication.

## Plan-checker revision: the em dash gates were blind to a staged file

The file-scoped em dash checks in tasks 1 and 3 took their diff with a bare `git diff -- <file>`,
which compares the worktree with the index and therefore sees nothing once the file has been
staged. Task 3's own file-list gate two lines above already reasons explicitly about "staged and
unstaged together", so the plan itself expects the executor may have staged `15-SPEC.md`; on that
path the em dash check diffed nothing, `grep` exited 1, and the gate passed on prose it never read.
Task 3's amendment was the more exposed of the two, because at that point its only backstop was the
phase-level em dash sweep in task 2, and that sweep runs before task 3 writes, so the amended spec
had no working check at all. That is the before-state and not the current one: the corrected
file-scoped gate described below is now `15-SPEC.md`'s own working check, and the phase-level sweep
is not its backstop.

Both now use a staged-tolerant base. `AGENTS.md` diffs against `main`, matching the phase-level
sweep and staying live even after task 1 has committed, which `HEAD` would not. `15-SPEC.md` diffs
against `HEAD`, matching the file-list gate beside it, because that file does not exist at the
merge base and a `main` diff would render the whole document as added and turn a check on the
amendment into a check on the entire file. Both were reproduced before the fix was written: with an
em dash staged into `AGENTS.md`, the old form matched nothing and the two corrected forms both
matched the added line. Recorded as T-15-44.

Both exemptions are safe for the same reason. Each gate reads a specific external file, `AGENTS.md`
in the first case and `15-SPEC.md`'s acceptance section in the second, and neither reads any file
this plan writes. No prose in this plan body can reach either target, so the literal appearing here
cannot make a gate report a regression that did not happen. Both gates remain live, and the
repository-wide sweep in task 2 covers the plan body itself under a different pattern.
