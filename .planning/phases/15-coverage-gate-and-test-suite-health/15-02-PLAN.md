## Commit convention

`AGENTS.md` governs every commit this plan makes: Conventional Commit messages, no GSD phase or
plan number as the scope (`15`, `phase-15` and `15-02` are planning bookkeeping, not repository
components; omit the scope when no stable repository-specific scope applies), and
`git commit -S -s` so the commit is GPG-signed and carries the developer sign-off.

Commit granularity is load-bearing here, not stylistic. Task 1 is a pure rename set and must be
its own commit with no content change in it, because that is what makes `git mv` rename detection
survive and `git log --follow` continue to trace each moved file. Fold task 2's content edits into
the same commit and the rename similarity drops below git's threshold, the moves are recorded as
delete-plus-add, and fourteen months of measurement-script history stops being reachable from the
new paths. Task 2 and task 3 then take their own commits in turn.

## Cross-AI review revisions, round 2

Round 2 rated this plan's relocation sound and its mechanisms verified, and found three ways its
own gates could report success without having measured anything. All three are fixed.

**HIGH, fixed: the privacy scan flagged legitimate fixtures and was blind to others.** Two halves,
both reproduced against this repository.

*The false-flag half.* `tests/test_scripts/test_ipv6_thread_probe.py` is in this plan's relocating
set and contains `fe80::1` and `fe80::20%en0` at four sites. The recorded IPv6 inventory held only
`fd00::20`, `fd00:1::` and `fd00:1::20`, and the action told the executor to replace anything
outside the inventory with a documentation-range value. The scan would therefore have driven the
corruption of valid link-local fixtures. The same defect was present, unreported by any reviewer,
in the MAC inventory: the tree carries nineteen MAC-shaped literals including `d0:73:d5:01:02:03`
and `02:00:00:00:00:01`, while the inventory admitted only the `00:00:5e:00:53:xx` documentation
range, so the scan would have condemned sixteen legitimate synthetic values. Every inventory below
is now the measured contents of the relocating file set rather than a recollection of it.

*The invisibility half, which is the worse of the two.* The serial scan's pattern was
`d073d5[0-9a-f]{6}`, which cannot match the `020000000001` style synthetic serials in
`measure_merged_discovery.py` and its test, nor `a00000000001`. Those values were never printed
and never checked, while `T-15-05` claimed the scans covered the relocation. The pattern is now
`\b[0-9a-f]{12}\b`, which is the shape of a LIFX serial rather than the shape of one vendor
prefix, and the inventory it produces over the relocating set is exactly twenty values. The word
boundaries are load-bearing: without them the pattern also matches the twelve-character prefix of
the hex-digit string in `serial_mac_audit.py`'s validator, which is not an identifier at all.

**MEDIUM, fixed: the scans covered only one task's staged diff.** They read `git diff --cached`,
so task 1's rename commit and task 2's content edits were never scanned, despite `T-15-05`
claiming coverage of the relocation through a commit. The scans now read the relocated tree on
disk, through `git ls-files --cached --others --exclude-standard .planning/scripts`, which covers
every task's cumulative state, includes uncommitted edits to tracked files, includes new untracked
files, and excludes gitignored build artefacts such as `__pycache__`. The `NO-STAGED-DIFF` timing
machinery is deleted with it: a scan that can be run at any point in the plan cannot be defeated by
running it at the wrong moment. Its non-vacuity protection is kept in a stronger form, because the
on-disk scan can assert both that the file list is non-empty and that the extracted identifier set
is non-empty, neither of which a staged diff could guarantee.

Each scan also stops being a print-and-inspect step and becomes a gate. It subtracts the inventory
from the observed set and exits non-zero naming the residue, so a value outside the inventory fails
the command rather than relying on a reader comparing two lists by eye.

expected-**N** ones as printouts. `git status --porcelain | grep -c '^R'` wants at least eight, but

**LOW, fixed: revision prose still described a PCRE negative lookbehind.** The round-2 revision text

did not rewrite the prose describing it. The paragraph now describes normalise-and-rematch and
records that the lookbehind wording was never what the gate did.

**LOW, fixed: the "seven references across the three files" import count was imprecise.** Only four
of the seven are import statements; the other three are prose citations, corrected under a different
heading in the same task. The action now names all seven by file and line and says which four are
imports.

**LOW, fixed: the privacy gates cover four shapes and the rule covers more.** `AGENTS.md:19`

and the gates' reach now agree.
