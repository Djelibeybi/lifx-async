## Commit convention

`AGENTS.md` governs every commit this plan makes: Conventional Commit messages, no GSD phase or
plan number as the scope (`15`, `phase-15` and `15-01` are planning bookkeeping, not repository
components; omit the scope when no stable repository-specific scope applies), and
`git commit -S -s` so the commit is GPG-signed and carries the developer sign-off.

Commit granularity for the tracer. Task 1 performs two `git mv` operations and then edits the
relocated test in the same commit, and that is deliberate rather than an oversight. An earlier
draft of this plan asked for a content-preserving relocation commit and then rewrote the relocated
test inside the same task, which no single commit can satisfy. The zero-content-change requirement
is dropped here: the edits to `test_check_patch_coverage.py` are one import line plus one
`pytestmark` line in a file of several hundred lines, far above git's fifty percent rename
similarity threshold, so `git log --follow` still traces the file across the move. The pure-rename
discipline still applies where it is actually load-bearing, in plan 15-02's task 1, which moves
eight files at once and would drop below the threshold if content edits were folded in.

## Plan-checker revision: the collection gates read the wrong output format

All three of Task 1's `--collect-only` gates searched for a text shape this project's own
configuration never emits. `[tool.pytest.ini_options] addopts` begins with `-v`, pytest verbosity
is cumulative, and no plan in this phase removes that flag, so `pytest --collect-only -q` ran at
net verbosity 0. At that level `--collect-only` prints the indented `<Module>` and `<Function>`
tree, not one node id per line. Two gates were therefore vacuous and one could never pass, and the
defect survived three cross-AI review rounds and three checker passes because the deterministic
probes see a command that resolves and a `<fails_when>` that is present, which is exactly what a
gate looks like when it is green by construction.

Measured against this tree before the fix was written:

| command | matches |
|---|---|
| `pytest --collect-only -q ... \| grep -cE '^tests/'` | 0 |
| `pytest --collect-only -q ... \| grep -c '::'` | 40, every one an IPv6 literal inside a parametrised test name in the tree text |
| `pytest --collect-only -q -q ... \| grep -cE '^[^ ]+\.py::'` | 4844, one per selected item |

Every collection command now carries two `-q` flags, which lands on net verbosity -1 and prints
node ids. A second `-q` is used rather than `-o addopts=''` because the marker expression step 5
deletes from `addopts` is part of what these gates observe, and blanking `addopts` would remove the
subject along with the noise. Each gate also gained a positive control that asserts the output
really is node ids before any match or count is trusted, so the same class of defect fails loudly
instead of passing silently. The equality on the third gate was re-checked under real counts rather
than assumed: with the pre-change mechanism still in place the default collection printed 4844 node
ids against a reported selected figure of 4844, the unfiltered collection printed 4856, and the
summary reported 12 deselected, so the identity holds. It is recorded as T-15-42.
