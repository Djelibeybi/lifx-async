<objective>
Close UAT gap G-18-1: `MatrixLight.set_effect(FirmwareEffect.MORPH)` with no palette must
always send a non-empty palette, built from the device's own colours, because real firmware does
not start MORPH when `Tile.SetEffect` carries `palette_count=0`.

Purpose: on a real Luna, MORPH started with no palette on a device already showing several
colours silently did nothing (`get_effect()` reported OFF), because D-14 had the library send
`palette_count=0` for that case. Sending the device's own distinct colours started MORPH and it
visibly morphed. This plan implements the maintainer's decisions of 2026-09-24 (D-24 to D-26),
the planner-derived empty-result rule (D-27) and the helper structure (D-28), without touching
the Move path, which works on real hardware.

Output: `sample_effect_palette()` in `component_state.py`; `_derive_morph_palette()` that
always returns a non-empty palette or raises; the Morph tests rewritten for the new behaviour
(with the five `_GOLDEN_` constants untouched); `set_effect()` docstring, `docs/api/devices.md`
and `AGENTS.md` describing it.
</objective>

## Decisions this plan implements

Recorded in `18-CONTEXT.md` on 2026-09-24 (D-14 marked superseded for Morph, D-23 amended) and
reflected in the amended R10 of `18-SPEC.md`:

- **D-24, maintainer decision (2026-09-24):** MORPH with no palette always sends a non-empty
  palette. FLAME, SKY and explicit palettes keep their bytes (D-19).
- **D-25, maintainer decision (2026-09-24):** a multi-colour device's MORPH palette is its own
  colours, tiles flattened in tile order. 2 to 16 distinct colours: all of them, first-seen pixel
  order. More than 16: 16 pixels spaced evenly across the flattened device, then de-duplicated in
  sample order. "Spaced evenly" is fixed by the planner as pixel index `i * n // 16` for `i` in
  0 to 15 (`n` = flattened pixel count). The single-colour rule (D-15 to D-18) is unchanged.
- **D-26, maintainer decision (2026-09-24):** if the colour read fails (`LifxTimeoutError` or
  `LifxProtocolError`) when MORPH starts with no palette, the error propagates and nothing is
  sent. This reverses the Morph half of commit `5a9d254`. Move's read-failure fallback is
  unchanged.
- **D-27, planner (implied by D-24 and D-26, flagged for the maintainer):** an empty colour result
  raises `LifxProtocolError` naming the device before any send.
- **D-28, planner's structural choice:** a new pure helper `sample_effect_palette()` beside
  `derive_effect_palette()`; `_derive_morph_palette()` calls `derive_effect_palette()` first and
  `sample_effect_palette()` when it returns None. `derive_effect_palette()`'s code and contract
  (None means "not a single colour") stay as they are, so Move's `_derive_move_palette()`,
  `set_move_effect()` and their tests do not change at all. A mode flag on
  `derive_effect_palette()` was rejected: it would change a signature Move shares, add a branch
  Move never takes, and mix two policies in one function.

**The five goldens stay immutable.** `_GOLDEN_MORPH_NO_PALETTE_BEFORE` is kept byte-for-byte;
its test now asserts MORPH never produces those bytes again. No `_GOLDEN_` constant is edited,
removed or added.

**Emulator behaviour this plan relies on, verified by the planner against the locked
lifx-emulator-core 3.7.0 on 2026-09-24:** `emulator_devices[6]` (`d073d5000007`) has one tile of
64 zones, and `set_matrix_colors(0, colors)` with 64 distinct hues reads back all 64 in order;
`Tile.SetEffect` with a 16-colour palette reads back through `get_effect()` unchanged;
`tile_chain_light` has 5 tiles, and painting tile 0 red and tiles 1 to 4 blue reads back with
first-seen distinct colours `[Colors.RED, Colors.BLUE]`; with
`scenario_manager("devices", "d073d5000007", {"drop_packets": {707: 1.0}})` a
`get_all_tile_colors()` raises `LifxTimeoutError`, and an OFF set beforehand still reads back as
OFF afterwards. A 64-colour tile left on `emulator_devices[6]` did not disturb
`tests/test_devices/test_matrix.py`, `test_effect_palette.py`, `test_ceiling.py` or `tests/test_api`
(438 passed in one session).
