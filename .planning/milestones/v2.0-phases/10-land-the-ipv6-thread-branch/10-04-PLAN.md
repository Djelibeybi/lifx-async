<review_response>
Revised 2026-08-27 from `10-REVIEWS.md`. Changes landing in this plan:

- **Finding 1 (BLOCKING).** The previous Task 1 started the emulator and *then* called `setsockopt(IPV6_V6ONLY)`. `EmulatedLifxServer.start()` binds inside itself (`lifx_emulator/server.py:518-519`, `create_datagram_endpoint(local_addr=...)`), and setting `IPV6_V6ONLY` after a bind raises `OSError: [Errno 22] Invalid argument` on macOS. That was a setup failure on the development platform, not a portability caveat, and every IPv6 test would have errored during fixture setup. Task 1 now builds the socket itself, sets `IPV6_V6ONLY` **before** bind, and hands the pre-configured socket to `create_datagram_endpoint(sock=...)` through a small test-only `_Ipv6EmulatedLifxServer` subclass. The read-back assertion moves to `getsockopt`, which is legal at any time. **This exact sequence was executed against this machine during replanning and returned `family: 30, V6ONLY readback: 1`, while the old post-bind order returned `[Errno 22] Invalid argument`** — so the revised acceptance criteria are satisfiable and the old ones were not. SPEC AC 16's explicit-`V6ONLY` requirement is kept, not dropped; only the ordering changed.
- **Codex MEDIUM, folded into Task 2.** The Animator test proved only that a local IPv6 socket existed: `send_frame()` increments packet statistics immediately after `sendto()` (`animation/animator.py:416`) and never learns whether the datagram arrived. Task 2 now reads the colour back from the emulator after the frame run, so delivery is proven rather than assumed.
- **Codex MEDIUM, folded into Task 1.** Neither the skip path nor the `LIFX_REQUIRE_IPV6=1` fail path was ever exercised: local and hosted Ubuntu runs only take the successful-bind branch. Task 1 now unit-tests the probe logic with a mocked bind failure for both the unset and the required environment states.
- **Finding 13 (LOW), REJECTED with a mitigation.** The suggestion was to assert the Animator's family through `get_extra_info("socket").family` instead of the private `animator._socket`. That surface does not exist here: `Animator` sends through a raw `socket.socket` created at `animation/animator.py:396-398` and never wraps it in an asyncio transport, so `_socket` is the only observation point, and the branch's own family tests already assert through it. Task 2 keeps `animator._socket.family` and adds a comment in the test naming the private-attribute dependency so a future Animator refactor knows what it breaks — OpenCode's own fallback suggestion.
- **Antigravity LOW, folded into Task 1.** `get_free_port6()` asserts the port it returns is greater than 0, so a silently failed bind fails fast instead of handing back 0.
