<objective>
Extend `scripts/ipv6_thread_probe.py` — which lands whole in this PR via commit b88cdb9 and already drives the library's own primitives through records, ports and connect stages against real hardware — into the Thread hardware UAT harness (D-21): a control stage (`set_color`/`set_power`), an optional streaming stage, and emission of the `10-UAT-RESULTS.json` record that gates plan 10-06's merge (SPEC R9).

A second purpose-built harness was explicitly rejected (D-21: it would overlap the probe heavily). This plan writes the harness only; the hardware run itself happens in plan 10-06 against the PR head, after CI is green (D-22).

Purpose: the merge gate needs a recorded, reproducible control-path proof against a Thread MatrixLight.
Output: the extended probe with `--serial`, `--uat-output` and `--stream`, plus its automated test module.

<review_response>
Revised 2026-08-27 from `10-REVIEWS.md`. Changes landing in this plan:

- **Finding 2 (BLOCKING).** The previous restoration captured `get_color()` and power. That cannot restore a MatrixLight: `get_color()` returns a single triple, while a matrix device holds a per-pixel image. The full-state API is `get_all_tile_colors()` (`src/lifx/devices/matrix.py:610`) paired with `set_matrix_colors()` (`:954`). Both the control stage's `set_color()` and the streaming stage overwrite that image, so the old plan would have silently destroyed whatever was displayed on a production fleet device and had no way to put it back. Task 1 now captures full tile state, power and any running firmware effect, and restores all three in a `finally`. Antigravity listed the old approach as a *strength* mitigating T-10-13; the API check refutes that, and T-10-13's severity is raised to high accordingly.
- **Finding 2, second half.** Restoration and `Animator.close()` were not required to be in `finally` blocks, so a control or streaming exception could leave both device state and a socket behind. Both are now mandatory `finally` work.
- **Finding 5 (HIGH).** The plan added substantial conditional CLI, error-handling, mutation and JSON logic and verified only `--help`, Ruff and Pyright. New Task 3 adds `tests/test_scripts/test_ipv6_thread_probe.py` covering target selection, the passed/failed/not_run states, JSON writing, streaming's non-gating behaviour, and restoration after injected failures, driven by fake devices with no hardware and no network.
- **Finding 5, coverage treatment — recorded, not weakened.** `pyproject.toml:117-118` scopes `--cov` to `lifx` and `generate_theme_data` only, so the probe is unmeasured, while `codecov.yml:17-42` scopes every flag's paths to `src/lifx/` and `scripts/`. This plan deliberately does **not** add the probe to the global `addopts`: `scripts/mdns_probe.py` and `scripts/serial_mac_audit.py` are equally unmeasured hardware diagnostics, and pulling a 521-line hardware script whose three original stages cannot run without real devices into the measured set would push the 90% project status down and create pressure to lower it — which prohibition 3 forbids. Instead the new logic is factored into named pure helpers that ARE tested, and Task 3's verify runs a **scoped** coverage report over the probe and fails if any line inside those helpers is missing. The patch gate is untouched: `pyproject.toml` and `codecov.yml` are not edited in this plan.
- **Finding 6 (MEDIUM).** The branch probe's argparse has only `--timeout`, `--stage` and `--verbose`; there is no `--serial`. Plan 10-06 Task 2's operator command depends on it, so one missing flag would turn the blocking hardware checkpoint into a decode-failure loop. Task 1 now adds `--serial` explicitly and the `--help` acceptance criterion checks for it by name.
